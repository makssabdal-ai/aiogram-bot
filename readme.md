# Боты кондитерской: Telegram и VK

Каталог тортов, фотографии и видео работ, отзывы, согласие на обработку данных и форма заказа.
Telegram и VK запускаются отдельными Python-процессами и используют общую PostgreSQL-базу.
Заказы с обеих платформ отправляются администраторам в Telegram.

## Требования

- Python: проверено на **3.14.3**, Windows. Минимальная поддерживаемая версия не закреплена и не тестировалась отдельно.
- PostgreSQL: локальная работа и миграция проверены на **18**.
- Зависимости — [requirements.txt](requirements.txt): aiogram 3, aiohttp, asyncpg и другие пакеты.
- Постоянно работающий компьютер/сервер с доступом к PostgreSQL, `api.telegram.org`, VK API и выданному VK адресу Long Poll.
- Telegram-токен бота; для VK — токен сообщества с доступом к сообщениям и ID сообщества.
- В сообществе VK должны быть включены сообщения, Long Poll API и события `message_new`, `message_event`.

Измеренных минимальных требований к CPU/RAM нет. Для небольшой нагрузки ориентир для **двух процессов ботов без PostgreSQL** — 1 vCPU и 1 ГБ RAM; это оценка для старта, не результат нагрузочного теста.
Для совместного размещения PostgreSQL и ботов ресурсы и диск нужно подбирать отдельно по объёму данных и резервных копий.
Медиа отправляются по идентификаторам платформ; каталог `files/` содержит исходные материалы, но не загружается автоматически.
Входящий HTTP-порт для ботов не требуется: используются polling и Long Poll, а не webhook.

## Установка

Откройте PowerShell в корне проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Создавайте окружение только при первоначальной установке. Для Linux соответствующий интерпретатор — `.venv/bin/python`; команды приложения те же, но работа на Linux здесь отдельно не проверялась.

## Настройка .env

При первой установке скопируйте [.env.example](.env.example) в `.env` и заполните его. Существующий `.env` не нужно заменять.
Файл должен быть сохранён в UTF-8 **без BOM**; `.env` исключён из Git.

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения PostgreSQL; нужна обоим ботам |
| `BOT_TOKEN` | Telegram Bot API token; нужен и VK-боту для уведомлений |
| `ADMIN_IDS` | Числовые Telegram ID администраторов через запятую |
| `VK_GROUP_TOKEN` | Токен сообщества VK |
| `VK_GROUP_ID` | ID сообщества: число, `club123456` или ссылка с `club123456` |
| `PERSONAL_DATA_CONSENT_URL` | Необязательная ссылка на документ согласия |
| `BOT_PROXY` | Необязательный HTTP-прокси, например локальный прокси VPN-клиента |
| `BOT_CA_FILE` | Необязательный путь к PEM-файлу дополнительной цепочки сертификатов для HTTP-сессий VK |

Для локальной PostgreSQL формат URL: `postgresql://USER:PASSWORD@localhost:5432/bot_cake`.
База и пользователь должны существовать заранее; пароль со спецсимволами требует URL-кодирования.
При старте приложение создаёт/дополняет таблицы. Пользователю БД нужны права на эти операции, а также чтение/запись данных и использование последовательностей.
Для `localhost`, `127.0.0.1`, `::1` SSL отключён; для удалённой PostgreSQL обязателен.

Telegram загружает `.env`, не перекрывая переменные процесса. VK загружает его с `override=True`.
Администратор должен предварительно открыть Telegram-бота и нажать «Старт», чтобы бот мог писать ему.

## Запуск Telegram отдельно

1. Запустите PostgreSQL и проверьте `DATABASE_URL`.
2. Заполните `BOT_TOKEN` и `ADMIN_IDS`.
3. Если задан `BOT_PROXY`, запустите соответствующий прокси/VPN-клиент.
4. Выполните из корня проекта:

```powershell
.\.venv\Scripts\python.exe -u -X utf8 main.py
```

Откройте бота в Telegram и отправьте `/start`. Процесс должен оставаться работающим.
Сообщение о запуске polling выводится до первой проверки API; проверьте отсутствие последующих ошибок.

## Запуск VK отдельно

1. Запустите PostgreSQL.
2. Заполните `VK_GROUP_TOKEN`, `VK_GROUP_ID`, `DATABASE_URL`, `BOT_TOKEN`, `ADMIN_IDS`.
3. Включите настройки сообщества, перечисленные в требованиях, и прокси, если он указан.
4. Выполните из корня проекта:

```powershell
.\.venv\Scripts\python.exe -u -X utf8 main_vk.py
```

Напишите сообществу «старт». Сам процесс Telegram-бота для отправки VK-заказов администраторам не нужен: VK-бот обращается к Telegram API самостоятельно.
Для одновременной работы запускайте команды в двух терминалах. Остановка — `Ctrl+C` в соответствующем терминале.
Не запускайте несколько экземпляров одной платформы с одним токеном.
Незавершённые диалоги хранятся в памяти и теряются при перезапуске; сохранённые пользователи и заказы остаются в БД.

## Схема данных и миграция

- `users.telegram_id` — положительный ID Telegram, `users.vk_id` — положительный ID VK. Оба столбца имеют независимую уникальность.
- В `orders` и `reviews` прежний `user_id` означает Telegram ID; для VK используется `vk_id`.
- API `Database` принимает ровно один идентификатор: `telegram_id=...` или `vk_id=...`.
- `catalog`, `works`, `reviews` содержат `file_id`/`media_type` для Telegram и `vk_file_id`/`vk_media_type` для VK.
- В заказах Telegram-вложение хранится в прежнем `media`, VK-вложение — в `vk_file_id`, его тип — в `vk_media_type`.

Схема создаётся в [database/db.py](database/db.py). [Миграция VK ID](database/migrations/001_vk_identity.sql) выполняется при `init_tables()` внутри транзакции и переносит старые отрицательные ID в положительные `vk_id`, очищая старое поле. Согласия и остальные данные записи сохраняются.
Повторный запуск безопасен; два процесса сериализуют инициализацию схемы через advisory lock.
Перед обновлением существующей базы сделайте резервную копию PostgreSQL и остановите старые процессы ботов.

## Загрузка VK-медиа

Список находится в [data/vk_media.json](data/vk_media.json). Каталог сопоставляется по названию без HTML, с нормализацией регистра и `ё`/`е`.
Все названия должны однозначно соответствовать существующим карточкам; импорт не создаёт описания товаров.
Отзывы и работы добавляются отдельными VK-строками без изменения Telegram-строк. Тип определяется по префиксу `photo`/`video`.

Проверка без записи (таблицы уже должны существовать):

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.import_vk_media
```

Применение к базе, указанной в `.env`:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.import_vk_media --apply
```

Повторный импорт не добавляет дубликаты отзывов и работ по `vk_file_id`; он обновляет соответствия каталога и типы VK-медиа.
Набор содержит 8 карточек, 16 уникальных отзывов и 49 работ (4 видео, 45 фото). Один повтор в исходном списке отзывов пропускается.
Идентификаторы вложений не заменяют резервную копию исходных фото/видео; доступность зависит от платформы и прав доступа.
Для закрытых вложений нужен актуальный `access_key` из данных VK для диалога сообщества.
Клиент проверяет наличие отправленных вложений через `messages.getById`: VK может принять текст, но отбросить фото.
Страница работ продвигается только после подтверждения вложений; при ошибке кнопка повторяет ту же страницу.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
.\.venv\Scripts\python.exe -m compileall -q main.py main_vk.py database handlers forms utils vk_bot scripts tests
.\.venv\Scripts\python.exe -m pip check
```

Без `TEST_DATABASE_URL` интеграционные тесты пропускаются. Чтобы включить их, задайте эту переменную строкой подключения тестовой PostgreSQL и повторите unittest-команду.
Тесты создают отдельную случайную схему `test_vk_*` и удаляют её после проверки; нужны права на создание схем.
Они проверяют разделение ID и согласий, сохранение заказов, повторную миграцию и импорт без изменения Telegram-медиа.
Сборка пакета, линтер и CI не настроены.

## Сетевые ошибки

- Таймаут `api.telegram.org`: проверьте доступ и `BOT_PROXY`. Для текущей локальной настройки используется HTTP-прокси Happ/Xray; клиент должен работать, порт должен совпадать с `.env`.
- `CERTIFICATE_VERIFY_FAILED` у VK: проверьте цепочку сертификата. Для локального окружения дополнительный промежуточный сертификат WR1 сохранён в `.local/wr1.pem`; этот файл не входит в Git. На другом устройстве потребуется собственная корректная цепочка или доступ без этой проблемы. Не отключайте проверку HTTPS.
- `BOT_CA_FILE` загружается при создании HTTP-сессии; неверный или отсутствующий файл остановит подключение.
- Ошибка подключения PostgreSQL: проверьте службу, существование базы, порт и учётные данные.
- Наличие строк в БД не подтверждает работоспособность отправки вложений: проверьте каталог, работы, отзывы и тестовый заказ в интерфейсе каждого бота.
